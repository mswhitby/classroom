### 1. Warm-up (5 min): Comparator reasoning

```java
class Word implements Comparable<Word> {
    String text;
    Word(String text) { this.text = text; }
    public int compareTo(Word other) {
        return other.text.length() - text.length();
    }
    public String toString() { return text; }
}
List<Word> words = new ArrayList<>();
words.add(new Word("cat"));
words.add(new Word("elephant"));
words.add(new Word("dog"));
Collections.sort(words);
System.out.println(words);
```

**Predict:** What prints? Does the comparison sort shortest-first or longest-first? What happens when two words have equal lengths?

<details>
<summary>Check and explain</summary>

`[elephant, cat, dog]`. The comparison subtracts this word's length from the other word's length, so longer words come first. Equal-length words compare as 0; the stable object-list sort preserves their relative order. Compare this behavior to the custom `Comparable` in Meet #1, Q26.

</details>

### 2. Learn (10 min): Priority queues and heaps

A Java `PriorityQueue<Integer>` removes the **smallest** integer first by default. `peek()` reads the head without removing it; `poll()` removes it. **Printing a priority queue does not guarantee sorted order**: its iterator exposes heap order.

```java
PriorityQueue<Integer> q = new PriorityQueue<>();
q.offer(15);
q.offer(13);
q.offer(9);
System.out.println(q.poll());
q.offer(q.peek());
System.out.println(q.peek());
```

Predict each output. Draw the contents after each operation.

<details>
<summary>Check</summary>

`poll()` prints `9`; the remaining queue contains 13 and 15. `q.offer(q.peek())` inserts another 13; `peek()` prints `13`. A printed queue representation is not a promise of globally sorted order.

</details>

### 3. Practice (12 min): Postfix notation and BSTs

**A — Postfix:** Evaluate `8 5 + 2 * 2 + 4 / 3 +`. For each token, record the stack; when using subtraction or division, the first popped number is the **right-hand operand**.

**B — Binary search tree:** Insert `50, 10, 5, 100, 30, 75, 37, 23, 150` in that order. Draw the tree and answer: How many leaves? What is its height measured in edges? How many levels?

**C — Extension:** For `int[] n = {5, 1, 4, 2}; Arrays.sort(n);`, distinguish the final sorted result from *which sorting algorithm* a particular Java implementation uses. Why is knowing the library specification different from recognizing an algorithm?

<details>
<summary>Check</summary>

- A: `10`: (8+5)=13; ×2=26; +2=28; ÷4=7; +3=10.
- B: **5 leaves**, **3 edges high**, **4 levels**. Draw paths to 5, 23, 37, 75, and 150.
- C: Final array `[1, 2, 4, 5]`. A library's chosen implementation is a separate question from the sorted output; use the contest's specified Java version and answer key when discussing implementation-specific questions.

</details>

### 4. Challenge (8 min): Trace an unfamiliar collection

```java
TreeSet<Integer> s = new TreeSet<>();
s.add(12);
s.add(5);
s.add(12);
s.add(8);
System.out.println(s.add(5));
System.out.println(s);
```

Predict both lines. Then explain how `TreeSet` differs from `HashSet` and `ArrayList` in duplicates and ordering.

<details>
<summary>Check</summary>

`false`, then `[5, 8, 12]`. Sets reject duplicates; `TreeSet` maintains sorted order, `HashSet` does not guarantee iteration order, and `ArrayList` allows duplicates and preserves positional order.

</details>

### 2. Learn (10 min): Increment and short-circuit tracing

```java
int a = 5;
int b = 6;
if (a++ > b || b >= ++a)
    System.out.print("yo");
System.out.print("wassup");
```

Remember: `a++` compares the old value before incrementing; `++a` increments first. `||` skips the right side only when the left side is true.

| Expression | Value of a afterward | True or false? |
|---|---|---|
| Start | 5 | — |
| `a++ > b` | ? | ? |
| `b >= ++a` | ? | ? |

Predict the exact output. Then change `b` to 4 and trace again.

<details>
<summary>Check</summary>

With `b=6`: the first comparison is false and `a` becomes 6; the second increments `a` to 7 and is false. Output `wassup`. With `b=4`: the first comparison is true, `a` becomes 6, the second is skipped, and output is `yowassup`.

</details>

### 3. Practice (12 min): Nested loops and array indices

**A — Count iterations:**

```java
int count = 0;
for (int i = 0; i < 4; i++)
    for (int j = 0; j <= i; j++)
        count++;
System.out.println(count);
```

Draw a table showing the number of inner-loop iterations for each `i`.

**B — Track array assignment:**

```java
int[] values = {3, 4, 5};
values[2] = values[0];
System.out.println(values[2]);
```

**C — Detect a boundary error:**

```java
int[][] mat = new int[5][5];
for (int i = 0; i < mat[i].length; i++) {
    mat[i][0] = i;
}
System.out.println(mat[3][0]);
```

What happens when `i` reaches 5? Fix the loop condition.

<details>
<summary>Check</summary>

- A: `10` iterations (1+2+3+4).
- B: `3`, because index 2 is overwritten with the value at index 0.
- C: `ArrayIndexOutOfBoundsException` before printing; use `i < mat.length` instead.

</details>

## Contest strategy and exit ticket

Written-test scoring: **+6 correct, −2 incorrect, 0 unanswered**.

A guess has positive expected value only when your probability of being correct is greater than **25%**. If you can narrow a multiple-choice question to two or three plausible answers, answering is usually a better scoring decision than leaving it blank. First secure questions you know, mark time-consuming ones, scan the entire test for accessible questions, and return to harder problems.

**Exit ticket (write 2–3 sentences):**
1. Which tracing mistake will you watch for next time?
2. What evidence tells you whether a loop or array expression is safe?
3. What will you practice before our next UIL meeting?

**Before you leave:** Explain one answer to someone else using a variable table, diagram, or stack trace.
