# Build, test, and share a project

## A build is a separate test

Saving a scene does not publish a game. A build packages the scenes and assets for a target platform. Include the intended scenes in the build list and test the starting scene. Follow the Unity companion for the build UI in your Editor version.

## Test the web build

Use the Web platform target (called WebGL in older versions). Test the built game through a web server or supported hosting service rather than opening its HTML as a local file. Check loading, controls, audio, and scene transitions. Editor success alone is not a build test.

## Prepare portfolio evidence

Complete the bonus scene, capture a short video, and share the project following classroom directions. Include controls, a description of what you made, and asset credits. Test the shared link on another device.

## Create a short label

In C#, + joins two strings. For example, "Game: " + title produces a label. This console exercise practices a readable project label; it does not build or upload a Unity project.

## Try tracing this example

```csharp
string label = "Project: " + "Mural";
return label;
```

Before running it, predict which value changes. Then run a small test and explain what happened in your own words.
